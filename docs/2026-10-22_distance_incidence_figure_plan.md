## 사용자 제공 시험 조건

- 실내의 큰 유리창 앞에서 시험한다.
- 창틀에서 유리를 빼고 넣는 대조 시험은 불가능하다.
- 천장·바닥 점을 줄이기 위해 Radar cfg의 출력 각도 범위를 조정할 예정이다.
- 사용자는 대부분의 조건에서 검출/미검출이 뚜렷하고 일부 경계 조건만
  간헐적으로 검출될 것으로 예상한다. 이는 아직 측정 전 가설이다.

## 오늘 Figure가 답할 질문

> 이 유리창·실내 배경·고정 Radar 설정에서 거리와 입사각에 따라
> 유리 내부 위치의 검출 비율과 검출점 SNR이 어떻게 달라지는가?

거리와 입사각은 모두 시험의 독립 변수다. 거리별 입사각 곡선은 두 요인의
결합 조건을 표시하는 방식이며 거리를 단순 보정값으로 취급하는 뜻이 아니다.
같은 입사각에서 거리 효과, 같은 거리에서 입사각 효과를 모두 비교할 수 있도록
조건을 배치한다. 실제 측정점 간격과 수는 2단계에서 정한다.

기존 제안의 유리 없음 패널은 삭제한다. 다른 장면을 유리 없음 대조군으로
대체하지 않는다. 따라서 오늘 시험만으로 배경 오검출률이나 유리 부재 판정
정확도를 산출할 수 없다. 유리 내부 위치의 점이라는 공간적 지지와,
반사의 물리적 원인이 유리라는 입증은 구분한다.

## 본문 Figure 수정 제안: 3개 패널

| 패널 | 형태 | 축·표현 | 역할 |
|---|---|---|---|
| (a) | 실험 배치 도식 + 작은 현장 사진 | 유리·Radar·법선·거리 r·입사각 θ·조준 방향·분석 영역 | 시험 기하와 제외할 창틀·바닥·천장 표시 |
| (b) | 거리별 검출 비율 곡선 | x=입사각 [deg], y=유리 내부 지지 scan 비율 [%], 색=거리 [m] | 검출이 유지되는 조건과 전이 구간 확인 |
| (c) | 거리별 SNR 곡선 | x=입사각 [deg], y=검출된 유리 내부 점의 SNR 요약 [dB], 색=거리 [m] | 검출이 유지될 때 관측되는 SNR의 변화·분산 확인 |

거리별 선은 측정한 점을 연결하는 안내선이며, 측정하지 않은 구간의 정확한
임계각을 의미하지 않는다. 전이 구간이 날카로우면 마지막 안정 검출 조건과
첫 미검출 조건 사이의 범위로 보고한다. 거리·각도 격자는 2단계에서 정한다.

(b), (c)는 같은 거리 색상을 사용하고 가까이 배치한다. SNR은 검출된 scan마다
유리 내부 지지점 SNR 중앙값을 먼저 구하고, 조건별 분포를 요약하는 방식을
후보로 둔다. 정확한 집계·반복·불확실성 표시는 2단계에서 정한다.
미검출 조건의 SNR은 0 dB로 그리지 않고 결측/미검출로 표시한다.

점 개수는 저장·보조 분석 후보로 둔다. 본문에 필요하면 검출 비율과 별개로
scan당 유리 내부 점 수를 표시하되, 검출된 scan만의 점 수인지 정상 수신한
전체 scan의 점 수인지 구분한다.

## Heatmap의 위치

Heatmap의 목적은 거리와 입사각을 함께 봤을 때 안정 검출 영역과 미검출 영역의
경계를 요약하는 것이다. 값이 거의 0/100%여도 경계가 거리별로 다르면 의미가 있다.
반면 거리 조건이 적거나 선 그래프로 경계가 충분히 읽히면 본문에 중복 배치할
필요는 없다. 현재는 본문 필수 항목에서 제외하며, 격자 측정이 충분할 때만
전체 조건 요약 또는 보조 Figure로 고려한다.

측정하지 않은 칸은 미검출과 구분한다. 성긴 측정점 사이를 보간해 정밀한
관측 경계가 측정된 것처럼 표현하지 않는다.

## 큰 유리면에서 반사 위치가 이동하는 경우

Radar 정면축과 유리가 만나는 점, 정한 유리 기준점, Radar 원점을 유리
평면에 수직 투영한 점은 일반적으로 서로 다르다. 송수신 위치가 거의 같은
Radar와 매끈한 평면의 이상적인 정반사 기하에서는 수직 투영점 부근에서
돌아오는 반사를 고려해야 한다. 그 점이 실제 유리 내부·안테나 감도 범위·cfg
허용 범위에 있을 때, 정면축 교점보다 가까운 유리 위치가 검출되는 것이 가능하다.
실제 점이 반드시 이 위치에 생긴다는 예측이나 현재 장비 실측 결과는 아니다.

기준점까지 거리 r, 기준점 방향의 법선 기준 각도가 θ라면, 무한 평면까지
최단거리는 기하적으로 r*cos(θ)다. 예를 들어 r=3 m, θ=30 deg이면 약 2.60 m다.
수직 투영점이 유한한 유리 밖이면 이 위치의 유리 반사는 기대할 수 없다.

시험에서는 기준점 거리 주변의 좁은 구면 거리 구간만을 유리로 취급하지 않는다.
유리 평면과 유한 내부 영역에 대한 점의 위치를 보존한다. 기준점 주변 영역과
유리 내부 전체에서의 검출 여부도 필요에 따라 분리해 볼 수 있도록 설계한다.
검출점 위치·기준점과의 변위·FoV 포함 여부를 확인하는 것이 2단계의 추가 항목이다.

기준점 입사각이 커져도 같은 유리의 다른 위치에서 국소적으로 작은 입사각의
반사가 검출될 수 있다. 따라서 이 시험의 각도는 기준점 방향의 관측 기하이며,
모든 검출점에서 동일한 국소 입사각을 가진다는 뜻이 아니다. 큰 유리 전체의
검출 가능 조건과 특정 위치의 입사각별 반사 특성을 구분해서 해석한다.

## 연속 미검출 그래프를 선택 항목으로 변경한 이유

기존 (d)는 같은 검출 비율이라도 미검출이 짧게 흩어지는지 길게 연속되는지
구분하고, 기존 설계의 연속 무응답 판정 시간(초기값 2 s)을 검토하기 위한 제안이었다.
이는 단순 거리·입사각 관측 특성보다 시간 판정 설계에 가까운 질문이다.

오늘 모든 조건이 거의 항상 검출/항상 미검출로 나뉜다면 추가 설명력이 작다.
따라서 본문 필수 항목에서 제외한다. 경계 조건에서 간헐 검출이 실제 관측되고,
시간 누적 기준을 정할 필요가 생길 때 해당 조건의 시계열과 미검출 구간 길이를
후속 분석한다. 시간 순서와 빈 scan 기록 가능성은 확보해 두는 방향을 2단계에서 검토한다.

## 위치 배치: 수직 이격거리와 기준점 거리의 선택

기준점까지 직선거리 r을 고정한 원호에서 각도 θ를 키우면 유리 평면까지의
수직거리 d=r*cos(θ)가 줄어든다. 예를 들어 r=1 m, θ=60 deg이면 d=0.5 m다.
이는 기하적으로 예상되는 변화이며 r과 d를 같은 거리로 명명하지 않는다.

유리와의 수직 이격을 고정하고 싶다면 유리와 평행한 선에서 좌우로 이동한다.
높이가 같은 고정 유리 기준점을 C로 정하고 그 정면 위치에서 옆으로
x=d*tan(θ)만큼 이동하며, 각 위치에서 센서를 C로 조준한다.
이때 r=d/cos(θ)로 증가한다. 센서 yaw만 제자리에서 바꾸는 것은 이 배치가 아니다.

| θ [deg] | d [m] | 옆 이동량 x [m] | 기준점까지 r [m] |
|---|---|---|---|
| 0 | 1.0 | 0.000 | 1.000 |
| 30 | 1.0 | 0.577 | 1.155 |
| 45 | 1.0 | 1.000 | 1.414 |
| 60 | 1.0 | 1.732 | 2.000 |

고정 실내 창 앞에서 이격 유지가 중요하면 이 평행선 배치를 권장하는 수정안이다.
다만 r과 d를 모두 고정하면서 θ만 바꿀 수는 없다. 이 배치도 기준점까지의
전파 경로 길이가 변하므로 각도 하나만의 효과를 완전히 분리한 시험으로 부르지 않는다.
여러 d와 θ 조합을 측정하고 r도 함께 기록하는 방향으로 설계한다.

최종 거리 축은 아직 사용자와 논의 중이다. 수직거리를 본 시험 축으로 택하면
명령행과 결과에 plane_distance_m, reference_range_m, incidence_angle_deg를
구분해 보존한다. 기존 항법 모듈의 valid_range는 후보 중심까지 거리이므로
수직거리로 의미를 바꾸지 않는다. 유한 유리 범위·조준점·검출점 위치와 FoV도
함께 확인해 다른 유리 위치의 반사를 구분할 수 있도록 한다.

## 정의와 해석 범위

- 거리 r: Radar 원점과 정한 유리 기준점 사이의 3D 직선거리 [m].
  평면까지의 최단 수직거리와 구분한다.
- 입사각 θ: 유리 법선과 기준점에서 Radar 원점으로 향하는 벡터 사이의 예각 [deg].
  정면 0°이며 센서 광축과 타깃 방향 사이 각도와 구분한다.
- 좌우 접근 방향을 시험하면 부호 있는 sweep 각도를 별도로 보존하고,
  대칭성을 확인하기 전에 합치지 않는다.
- 지지 scan: 사전에 정한 유한 유리 내부 공간 게이트에 점이 하나 이상 있는
  서로 다른 실제 hardware scan. 점이 0개인 정상 scan도 분모에 포함한다.
- sensor yaw만 제자리에서 바꾸면 고정 유리 기준점에 대한 입사각이 바뀌는 것은
  아니다. 실제 위치·평면 법선·관측 영역과 센서 조준 방향을 구분해야 한다.
- 센서 FoV/분석 영역이 거리·각도에 따라 타깃을 잘라내는 경우,
  FoV에 의한 누락을 유리 자체의 각도 반사 특성으로 해석하지 않는다.
- 이 결과는 시험한 유리·실내 배경·Radar 설정의 관측 특성이다.
  유리 제거 대조군 없이 유리 부재 판정의 오판율을 주장하지 않는다.
- 기존 설계의 1–5 m, 10°, 2 s는 미검증 초기값이며 검증된 기준으로 쓰지 않는다.

## SNR 검토

현재 parser는 TLV type 7의 SNR/noise를 0.1 dB 단위에서 dB로 변환한다.
현재 publisher는 SNR을 PointCloud2의 intensity에 넣는다. 실제 장비에서
side-info TLV가 수신되는지와 값이 유효한지는 아직 이번 세션에서 확인하지 않았다.

TI SDK 3.x 자료의 SNR은 검출 cell과 주변 noise 사이의 비다. 절대 반사 전력이나
유리 재질 자체의 반사율로 명명하지 않는다. 검출점에 딸린 값이므로 검출되지
않은 표면 위치의 SNR까지 현재 점군으로 얻는 것은 아니다.

따라서 검출 비율과 함께 읽어야 한다. 약한 점이 검출 목록에서 빠지면 남은 점의
SNR만으로는 신호가 약해진 정도가 드러나지 않을 수 있다. 거리가 멀거나 각도가
커질수록 출력 SNR이 반드시 단조 감소한다고 미리 가정하지 않는다.

구현 전 소스는 side-info가 없을 때 NaN을 0으로 바꿨다. 후속 수정에서는
NaN을 그대로 보존하고 CSV/JSON에서는 결측으로 저장하도록 변경했다.

## cfg 각도 제한 검토

현재 radar.cfg는 aoaFovCfg -1 -70 70 -30 30을 사용한다.
TI SDK 문서상 이 명령은 지정한 azimuth/elevation 밖의 검출점을 거르는 설정이다.
물리적인 송수신 빔 폭을 바꾸거나 실내 반사·다중경로를 제거하는 설정으로
해석하지 않는다.

따라서 창틀의 강한 반사가 유리의 검출을 방해하는 상황에서, FoV 밖 점을
출력에서 제외하는 것만으로 앞선 검출 과정의 방해까지 해소된다고 기대하지 않는다.
이는 문서의 필터 정의에서 도출한 해석이다. 현재 장비의 firmware 구현까지
확인한 것은 아니므로, 넓은/좁은 FoV에서 공통 영역의 결과가 완전히 같다고
단정하지 않는다. 출력점 증가에 따른 전송량·수신 누락도 함께 살펴야 한다.

본 측정 전 같은 거리·입사각·조준·분석 영역에서 넓은 FoV와 좁은 FoV를
비교하는 준비 시험을 제안한다. 다른 cfg 명령은 동일하게 유지하고 순서를
넓음→좁음→넓음 등으로 바꾸어 반복한다. 공통 유리 내부 영역의 검출 비율,
SNR, 점 수 및 hardware frame 수신·누락을 비교한다. 별도 실행이므로
frame별 값의 일치를 요구하지 않고 반복 분포와 누락 상태로 비교한다.
공통 영역 밖의 점이 줄어든 것과 유리 검출 자체가 달라진 것을 구분한다.

저장된 장착축 추정값에서는 raw radar azimuth 평면이 카메라 기준 수직–전방에
대응한다. 현장 장착과 같은지 확인한 뒤 천장·바닥 제한에 해당하는 축을 정한다.
일반적인 elevation=상하라는 가정만으로 수치를 정하지 않는다.

설정은 시험 준비 시 정한 뒤 본 측정 중 고정하는 것을 기본으로 한다.
불가피하게 바꾸면 설정별 시험으로 구분한다. 유리 내부 공간 게이트도 사용하며,
출력 각도 제한만으로 창틀·바닥·천장 분리가 끝났다고 취급하지 않는다.
구체적인 수치와 기준 기하 확보 방법은 2단계에서 정한다.

## 구현 전 문제와 후속 수정 기준

- 구현 전 publisher는 최신 점 배열을 timer로 발행하고 빈 점군은 발행하지 않았다.
  기존 ROS 메시지 수를 서로 다른 hardware scan 수로 그대로 사용할 수 없다.
- 구현 전에는 새 frame이 없는데 이전 배열이 남아 있으면 새 ROS timestamp로 재발행할 수 있었다.
  정상 0점 frame으로 배열이 비어도 빈 메시지를 보내지 않으므로 표시 측에서
  마지막 점군이 남을 수 있다. 두 경우를 구분해서 수정·확인한다.
- 후속 수정에서 packet 재조립·frame 식별·누락 구분·빈 scan 보존을 구현하고
  합성 입력·가상 UART/ROS/launch로 확인했다. 실제 장비 연결 검증은 남아 있다.
- radar-camera extrinsic은 calibrated: false인 추정값이다.
  기준 기하를 이 추정 TF나 YOLO 출력만으로 정답 처리하지 않는다.

3단계 수정의 필수 동작은 다음과 같다.

- 서로 다른 정상 hardware frame 하나당 한 번 발행하고 이전 frame은 재발행하지 않는다.
- 전체 검출점 0개인 정상 frame은 빈 PointCloud2로 발행한다. 다른 물체 점은
  있으나 유리 내부 점만 없으면 원본 점군은 유지하고 유리 지지 수만 0으로 기록한다.
- frame 번호, host 수신 시각, 전체 점 수와 유리 지지 수를 추적·저장한다.
  host 수신 시각을 센서 자체의 측정 시각으로 명명하지 않는다.
- 통신/파싱 실패와 frame 누락은 정상 0점 관측으로 채우지 않고 별도 상태로 기록한다.
- 회귀 검증에는 비어 있지 않은 frame→0점 frame→다음 frame, 새 입력 없음,
  여러 packet 동시 수신·분할 수신, frame 번호 누락을 포함한다.

## 명령행 시험 조건과 결과 저장 요구사항

사용자는 실행 명령에 거리·입사각을 넣고 코드 파라미터로 전달하며, 결과에도
같은 값이 보존되도록 요청했다. 전용 radar_distance_angle_test.launch.py에서
plane_distance_m, incidence_angle_deg, trial_id와 선택 off_axis_deg를 받도록
구현했다. 기존 bag_record.launch.py에 같은 인자를 추가한 것은 아니다.
Radar 기동과 직접 기록을 한 과정에서 수행해 실제 cfg와 입력값을 보존한다.

- 입력값은 해당 시행의 기준 거리·입사각으로 기록한다. Radar가 자동 측정한
  값으로 표시하지 않는다. 실제 기하·분석 영역과 연결할 필요가 있는지도 2단계에서 정한다.
- 명령행→실제 분석 코드 파라미터→시행 메타데이터→조건별 요약 결과까지
  값과 단위를 일관되게 전달한다. bag 이름에만 담지 않는다.
- run별 메타데이터에 거리[m], 입사각[deg], 반복 ID, 시험 시각, 실제 실행 인자,
  코드 버전과 변경 상태, 분석 영역 정의, cfg 원문 사본·hash·FoV 범위를 남긴다.
- cfg 경로가 같아도 내용은 바뀔 수 있으므로 경로만 보존하지 않는다.
  Radar 기동과 기록이 분리되어 있으므로 실제 기동 때 사용한 cfg와 기록 측의
  메타데이터가 일치해야 한다. cfg 명령 응답 등 적용 확인 근거도 보존하는 방향으로 설계한다.
- 정상 0점 scan은 검출 수 0, SNR 통계 없음으로 저장한다. 미검출점의 좌표나
  SNR 행을 만들어 넣지 않는다. SNR side-info 누락은 점 자체의 미검출과 구분한다.
- 테스트에는 입력값 검증, 서로 다른 거리·각도 조합의 전달·저장 왕복,
  결과에서 단위·반복 ID·cfg 일치, 0점 상태의 SNR 결측 처리를 포함한다.

Figure 논의 이후 사용자의 요청으로 코드까지 수정했다. radar.cfg 내용과
extrinsic은 변경하지 않았으며 실제 센서는 실행하지 않았다.
